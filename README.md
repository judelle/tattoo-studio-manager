# Tattoo Studio Manager

Tattoo Studio Manager — внутренняя CRM-система для управления тату-студией, разрабатываемая на Go.

Проект создаётся как реальный рабочий инструмент для ведения клиентов, записей на сеансы, расписания, стоимости работ и истории посещений.

Разработка начинается с консольного приложения: на этом этапе реализуется основная бизнес-логика. В дальнейшем проект будет развиваться в полноценное backend-приложение с REST API, PostgreSQL, Telegram-ботом и веб-интерфейсом.

**Текущее состояние:** реализованы основные операции с клиентами и записями, работа с московским временем и первичное разделение проекта по пакетам. Данные пока хранятся в памяти во время работы программы; сохранение между запусками будет добавлено на этапе JSON.

## Основной функционал

### Реализовано

- Добавление, просмотр, поиск по ID, редактирование и удаление клиентов.
- Валидация данных клиента и проверка уникальности номера телефона.
- Создание записей на тату-сеансы с привязкой к клиенту.
- Просмотр расписания на выбранную дату с сортировкой по времени.
- Проверка корректности даты и времени, запрет записи в прошлое и проверка занятого времени.
- Перенос записей, включая возврат отменённой записи в статус `planned`.
- Отмена записи и завершение сеанса с указанием фактической стоимости.
- Учёт плановой стоимости и предоплаты.
- Безопасное удаление ошибочно созданной записи в статусе `planned`.
- Защита завершённых и отменённых записей от удаления.
- Запрет удаления клиента, к которому привязаны записи.
- Работа с датами и временем в московской временной зоне.

### Планируется

- Просмотр истории записей конкретного клиента.
- Просмотр будущих записей.
- Хранение нескольких эскизов для одной записи.
- Постоянное хранение данных: сначала JSON, затем PostgreSQL.
- Напоминания о предстоящих сеансах.
- REST API, Telegram-бот и веб-интерфейс CRM.

## Архитектура

Проект уже разделён на пакеты: консольный интерфейс находится в `cmd/console`, модели, поисковые функции и вспомогательная логика — во внутренних пакетах приложения.

Текущая структура:

```text
cmd/
└── console/
    ├── main.go
    ├── client_console.go
    └── appointment_console.go

internal/
├── client/
│   ├── model.go
│   └── service.go
│
├── appointment/
│   ├── model.go
│   └── service.go
│
└── datetime/
    └── timezone.go
```

- `cmd/console` — запуск приложения, меню, ввод и вывод данных.
- `internal/client` — модель клиента, поиск и вспомогательные операции с клиентами.
- `internal/appointment` — модель записи, статусы, поиск и вспомогательные операции с записями.
- `internal/datetime` — общая настройка московской временной зоны.

Разделение ответственности продолжается: часть бизнес-правил пока находится в консольном слое. Следующие шаги — завершить их перенос в сервисы, добавить слой хранения данных (`repository`), а затем HTTP API и внешние интерфейсы.

Цель архитектуры — использовать одну бизнес-логику в консольном приложении, REST API, Telegram-боте и веб-интерфейсе. Структурная валидация будет проверять форму входных данных, а сервисы — бизнес-правила: допустимые изменения статуса, занятость времени и ограничения на удаление.

## Технологии

### Используется сейчас

- Go и Go Modules.
- `github.com/google/uuid` — генерация UUID.
- Стандартные пакеты Go: `time`, `slices`, `bufio`, `sort` и другие.

### Планируется

- JSON — первоначальное постоянное хранение данных.
- `go-playground/validator/v10` — структурная валидация входных данных и DTO.
- `chi` — маршрутизация HTTP-запросов.
- REST API — доступ к функциям приложения через HTTP.
- PostgreSQL — основная база данных.
- `pgx/v5` — работа с PostgreSQL.
- `golang-migrate/migrate` — миграции базы данных.
- Стандартный пакет `testing`, затем при необходимости `testify` — автоматические тесты.
- OpenAPI / Swagger — описание и документация API.
- Telegram Bot API — интерфейс управления через Telegram.
- React + TypeScript — веб-интерфейс CRM.
- Docker / Docker Compose — упаковка приложения и запуск окружения.

Сторонние библиотеки будут подключаться по мере появления соответствующих задач. Для конфигурации через переменные окружения рассматривается `caarlos0/env`, для нормализации международных телефонных номеров — библиотека на базе libphonenumber, для работы с OpenAPI — `oapi-codegen`.

## Цели проекта

Проект создаётся как рабочая CRM для тату-студии и одновременно как практический backend-проект для изучения Go. Разработка идёт поэтапно: от консольного приложения и доменной логики к постоянному хранению данных, API и нескольким пользовательским интерфейсам.

В процессе разработки планируется изучить и применить:

- Проектирование моделей и бизнес-логики.
- Архитектуру Go-приложений и разделение ответственности между слоями.
- Работу с файлами и JSON.
- Unit-тестирование и табличные тесты.
- PostgreSQL, SQL и миграции базы данных.
- Разработку REST API и его документирование.
- Сторонние Go-библиотеки для типовых задач.
- Goroutines и channels там, где необходима конкурентная обработка.
- `context.Context` для управления временем жизни операций.
- Telegram Bot API и фоновые задачи.
- Взаимодействие backend и frontend.
- Docker и развёртывание приложения на сервере.

Практическая цель — создать удобный инструмент для ежедневной работы студии: ведения клиентов, управления расписанием, учёта стоимости сеансов и сохранения истории работы.
